# Content guide (public English)

Applies to this repo, the portfolio site, and copy reused on LinkedIn / resume.

## Voice

- Personal and concrete: first person ownership («I owned», «I shipped»)
- Alive, not corporate filler; still senior and scannable
- Outcome-first: challenge → what shipped → result → stack
- Section title **Practice** / **Lab**, never «Hobbies»

## Hard bans

- Do not mention Cursor, chatbots, or that text/code was drafted with an assistant
- Do not use the em dash character `—`; use comma, colon, period, or hyphen `-`
- No fluff adjectives without proof
- No client secrets, real hostnames, or ticket IDs

## Language

All public pages and README: **English**.

## ATS / recruiter search

Reuse the same canonical phrases (do not rotate synonyms every page):

- Titles: Platform Engineer, Cloud Infrastructure, AI Infrastructure, turnkey delivery
- Skills: Kubernetes, Terraform, Ansible, Helm, ArgoCD, GitOps, CI/CD, Docker, Linux, LLM, RAG, observability
- Put a **Stack** block on every case study
- LinkedIn headline / About / resume summary must share the same keyword cluster

Dense on keywords, light on water. Hiring filters and humans both scan fast.

## Limits

| Section | Max |
|---------|-----|
| Case study | ~400–700 words + 1 diagram |
| Practice card | 5–8 lines on site; md summary ≤ 120 words |
| Package page | scope, timeline, deliverables |

## Ratio

~80% case studies + reference infra/AI/apps  
~20% practice (workstation + home lab)

## NDA

Private client code stays private.  
Public = narrative + generic reference implementation.
